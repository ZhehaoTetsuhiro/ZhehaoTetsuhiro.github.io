速览

板上界面四进制数字编辑器：16 个数字 = 一条 32 位指令，一行 16 位 = 一条指令
寄存器128 位（MicroPython 整数本就是任意精度，一分钱不花）

电脑端工具asm / dis / run / keys / sim / push / pull
烧录自动找串口、打包、写入、读回校验、重启，带备份与失败回退

详细介绍

它是什么

一块掌控板上跑着的 TH128I 子集机器：屏幕上就是一串四进制数字（0 1 2 3），16 个数字 = 一条 32 位指令，一排 16 位 = 一整条指令；P Y T H O N 六个金指加 A B 两个大按键完成编辑、存 flash、运行。

板上机器

指令：基础整数全组（全宽度访存、ALU、立即数、分支、跳转、fence）与 M 扩展（mul/mulh/mulhsu/mulhu/div/divu/rem/remu，除零与溢出语义照规范）；ecall/ebreak 即停机。

刻意不实现：CSR、陷阱/特权级、浮点、向量、压缩指令、xRET —— 碰到就报错，绝不猜着往下跑（理由与取舍见 docs/设计.md）。

I/O沿用 tthr 的 tohost 约定，另加一个输入口：往 0x1000 写 (ch<<8)|1 打印字符、写 0 结束程序；从 0x1004 读一个输入字符。

编辑画面的两种看法：数字视图与反汇编视图（A+B 快点切换），长按 O/N 挪 16 位即上下挪一整条指令。

电脑上写程序 + 一键烧录

板上敲 16 下才出一条指令，长程序受不了 —— 所以在电脑上写汇编，一条命令推上去：

python3 tools/ta.py asm/dis/run/keys/sim/push/pull：汇编、反汇编、在电脑上跑、算出在板上该按哪几个键、终端里模拟掌控板、烧录 / 从板上取回。汇编语法就是 Tetsuhiro-Alpha 的那一套（伪指令、指示字、# 注释）。

tools/flash.py 自动找串口、打包、写入、读回校验、重启，支持 --program（顺便写进程序）、--monitor、--dry-run、--doctor（固件版本、文件列表、剩余空间，并把六个模块逐个 import 一遍）。

真板子上踩过的坑（都已修）：板上写文件必须 close()（MicroPython 没有引用计数，写完即丢会静默丢数据）；板上没有 bytes.fromhex，解码方式到板上现问；写前先问剩余空间；核对时一小块一小块读（大文件一口气读会 MemoryError）；等板子回话给足时间；老文件备份成 *.bak（已有就不动，最先备份的才是原件）；半路写炸会自动退回；main.py 最后才传，断在半路旧程序还能跑。

测试：tests/test_all.py 132 条（机器核心、汇编/反汇编往返、界面模型、整机剧本）+ tests/test_flash.py 34 条（拿假板子跑完整条写入 → 核对的路，含「砍掉 unhexlify 的假板子」与发给板子的每段代码的 MicroPython 解析）。

下载与安装

这个项目走「源码 + 一键烧录」而非预编译二进制：板上跑的是 MicroPython，固件与文件都由 tools/flash.py 直接写入掌控板。

本项目没有预编译二进制发布，直接用下面的命令从源码起步。

git clone https://github.com/ZhehaoTetsuhiro/Tetsuhiro-Alpha-on-mPython.git
cd Tetsuhiro-Alpha-on-mPython
pip install pyserial
python3 tools/flash.py --list        # 看看有哪些串口 / list serial ports
python3 tools/flash.py               # 打包、写入、读回校验、重启
python3 tools/flash.py --doctor      # 固件版本、文件列表、剩余空间
make check                           # 全部测试 / full test suite
